# DF, CoF, PoF, RISK, ФТС и ППК

Статус всех задач — запланированы. Общий контракт запуска описан в [00-foundation.md](00-foundation.md). Текущие ядра находятся в [frontend/src/domain/calculations](https://github.com/PandaDoddo/rline/tree/main/frontend/src/domain/calculations).

Перенос каждого ядра начинается с фиксации текущих входов/выходов и эталонов. Изменение методики получает отдельную версию и предметное решение. Известные расхождения с таблицами разобраны в [EXCEL_ERRORS.md](https://github.com/PandaDoddo/rline/blob/main/spec/EXCEL_ERRORS.md), незавершённые механизмы перечислены в [BACKLOG.md](https://github.com/PandaDoddo/rline/blob/main/spec/BACKLOG.md).

## F18. Факторы повреждения DF

Сущности — запуск DF, вход механизма/элемента/потока, инспекция, ручное переопределение, результат, сводка области. Зависимости — F04, F07–F17 и X07. Обязательные входы определяются отдельно для семейства механизма.

| ID | Задача | Критерий приёмки |
| --- | --- | --- |
| F18.01 | Инвентаризировать все входы и выходы семейств DF | Паспорт, материал, поток, активный МД, измерения, инспекции и ручной ввод сопоставлены с источником. Неприменимый и невозможный расчёт различаются |
| F18.02 | Подготовить эталоны и численную политику | Для каждого семейства есть нормальный, граничный и неполный набор, версия таблиц, точность, округление и объяснение известных отклонений от Excel |
| F18.03 | Перенести DFthin | Даты, номинальная/фактическая толщина, принятая скорость, число/категория инспекций и активность МД воспроизводят действующее ядро. Плакировка и неподдержанные варианты имеют явный статус |
| F18.04 | Перенести наружную коррозию Ext и CUI | Учитываются материал, атмосфера, изоляция, покрытие, температура, даты и инспекции по версии правил. Ручные значения сохраняют происхождение |
| F18.05 | Перенести наружный ClSCC и ClSCC под изоляцией | Применимость аустенитного материала, условия, даты и модификаторы проверены на границах. ExtClSCC и CUIClSCC имеют самостоятельные результаты |
| F18.06 | Перенести SSC/HIC-H₂S/HIC-HF/HSC-HF | Воспроизведены условия внутреннего контакта, показатели среды, инспекции и действующее взвешивание по потокам. Доля потока участвует в снимке входов |
| F18.07 | Перенести ACSCC, Amine SCC, Caustic SCC, ClSCC и PASCC | Каждое ядро имеет отдельный набор эталонов, модификаторов и таблиц. Экспериментальная PASCC-методика DIFF отделена версией от действующей |
| F18.08 | Перенести HTHA | Материал, pH₂, температура, PWHT и интерполяция кривых API 941 воспроизводятся с указанием использованной кривой. Нехватка входа объясняется |
| F18.09 | Перенести хрупкое разрушение, TE, 885 °F и sigma | Температурные базы, материал, кривая, J/X̄, сигма-фаза, FSE и интерполяция сохраняют ветки текущего кода и единицы |
| F18.10 | Реализовать разрешённые ручные входы и сброс к авто | `dfOv` сопоставлен с полями. Сброс возвращает вычисленное значение с источником, правка не меняет прошлый снимок расчёта |
| F18.11 | Реализовать сводки и агрегацию DF | Отдельно выдаются результаты элементов, сосуд и каждый змеевик. Максимумы и комбинации используют утверждённые правила. Неподдержанный DF не трактуется как подтверждённый ноль |
| F18.12 | Реализовать запуск, сохранение, детали и устаревание | Повтор запуска, отмена/ошибка операции и смена входов имеют определённый результат. Детали формул и источников доступны из сохранённого запуска |
| F18.13 | Перенести сохранённые `dfRes` и подключить DamageFactorsTab | Сохранённые результаты сохраняют статус legacy при неполной версии входов. Старые расчёты до разделения змеевиков помечаются к пересчёту |
| F18.14 | Выделить нерешённые механизмы в отдельные решения | По плакировке, усталости, футеровке, нескольким потокам thin и агрегации есть решение с границей реализации. Действующий поддержанный объём перечислен явно |

## F19. Последствия отказа CoF

Сущности — классификация элемента, поток выброса, сценарий отверстия, запас, меры защиты, стоимостные входы, запуск и этап расчёта. Зависимости — F03–F05, F07–F11 и X07. Группы запаса нескольких ЕО остаются отдельным предметным расширением.

| ID | Задача | Критерий приёмки |
| --- | --- | --- |
| F19.01 | Описать коды API 581, материал и геометрию для элементов | Код, gff/размеры, matcost и условия применимости имеют источник. Колонна и её верх/низ/середина сопоставлены с действующими правилами |
| F19.02 | Зафиксировать контракт CoF и эталоны | Входы смеси, давления, температуры, объёма, расхода и стоимости имеют единицы и версии. Эталоны включают газ, жидкость, токсичный и инертный поток |
| F19.03 | Перенести свойства и эффективную среду выброса | Расход использует согласованные свойства смеси, горючая масса — соответствующую долю, токсичные компоненты — свои доли и пороги. Ручные входы объяснимы |
| F19.04 | Перенести сценарии утечки и доступного запаса | Размеры отверстий, фаза/режим истечения, расход, масса и длительность воспроизводятся по ядру. Отрицательные и неполные физические входы блокируют расчёт |
| F19.05 | Перенести обнаружение, изоляцию и смягчение | Согласованные категории и коэффициенты влияют на этапы и отражаются в деталях. Источник каждой принятой категории доступен |
| F19.06 | Перенести горючие последствия | Площадь последствий и ветки сценариев совпадают с эталонами и исправлениями проекта. Инертная доля не создаёт горючих последствий |
| F19.07 | Перенести токсичные и NFNT последствия | Отдельно проверены подходящие токсичные среды и реализованные NFNT-ветки. Неподдержанная среда возвращает явное ограничение вместо произвольного аналога |
| F19.08 | Перенести финансовые последствия | Составляющие FC, стоимость компонентов, персонала, простоя и прочие реализованные части совпадают с входами установки/элемента и единицами результата |
| F19.09 | Реализовать категории и агрегацию | Категории A–E по площади/деньгам, максимумы элементов и потоков совпадают с текущей утверждённой логикой. Каждый максимум ссылается на источник |
| F19.10 | Реализовать ручные входы, историю и устаревание | `cofOv`, изменение вещества/потока/стоимости и классификации отслеживаются. Старый результат читается со своим снимком, новый запуск имеет самостоятельную версию |
| F19.11 | Перенести `cofRes` и подключить ConsequencesTab | Карточка расчёта показывает все доступные этапы, исходные значения и сохранённую дату. Сводка ФТС и реестр читают тот же результат |

## F20. Вероятность отказа PoF

Сущности — принятая совокупность DF, gff, FMS, запуск PoF, результат элемента и области. Зависимости — F18 и классификаторы F07/F19. Вычисленная площадь/стоимость CoF не является обязательной для самого PoF.

| ID | Задача | Критерий приёмки |
| --- | --- | --- |
| F20.01 | Зафиксировать контракт PoF и агрегации DF | Для каждого включённого DF определена группа и правило комбинации. Нет DF и подтверждённый нулевой DF различаются |
| F20.02 | Реализовать gff и FMS | Источник классификации и диапазон множителя указаны. Неполный код/коэффициент блокирует соответствующий элемент с объяснением |
| F20.03 | Перенести ядро `pofcalc` | Значение gff × FMS × принятый DF, единицы и групповые составляющие совпадают с эталонами, включая общий/локальный тип коррозии |
| F20.04 | Реализовать сохранение входов и связь с DF | Запуск ссылается на конкретный DF и версию классификатора. Повторный расчёт DF не переписывает прошлый PoF |
| F20.05 | Реализовать сводки по сосуду/змеевикам и признак устаревания | Области независимы. Недостаток данных одного элемента виден в полноте сводки |
| F20.06 | Перенести `pofOv`/`pofRes` и подключить ProbabilityTab | Ручные параметры и детали читаются после нового сеанса. Вкладка показывает результат, отсутствие входов и потребность пересчёта |

## F21. RISK и планирование инспекций

Сущности — целевые показатели, прогноз по элементу, сценарий инспекции, рекомендация, запуск риска. Зависимости — F12–F20, X07. Состав используемых сохранённых DF/PoF/CoF фиксируется контрактом F21.01.

| ID | Задача | Критерий приёмки |
| --- | --- | --- |
| F21.01 | Зафиксировать входы RISK и зависимости расчётных версий | Дата анализа, горизонт, шаг, DF/PoF, CA/FC и цели связаны с конкретными результатами. Использование устаревшего источника имеет явное правило |
| F21.02 | Перенести прогноз DF и PoF во времени | Ряды имеют согласованный шаг и точность, данные вне области применимости обработаны. Эталон включает отсутствующий механизм и несколько групп |
| F21.03 | Перенести риск по площади и финансам | Для каждой даты есть исходный PoF и CA/FC. Отсутствующая оценка последствий даёт отсутствие соответствующего риска |
| F21.04 | Перенести поиск пороговых дат | Пересечения целевых риска/PoF/DF/толщины и ограничения интервала воспроизводят интерполяцию и выбор определяющего фактора |
| F21.05 | Перенести сценарии инспекций и эффект категории | Результаты до/после показывают изменённые входы, дату и выбранную категорию. Прогноз не изменяет реальную историю проведённых инспекций |
| F21.06 | Реализовать рекомендуемые даты и объяснение | Для рекомендации видны ограничивающий критерий, горизонты, необходимость инспекции и недостаточные данные. Рекомендация отделена от принятого плана диагностики |
| F21.07 | Реализовать цели, сценарии и сохранение | `riskOv` и запуск имеют версию. Конкурирующее принятие параметров обнаруживает конфликт, новый сценарий не изменяет сохранённый результат |
| F21.08 | Согласовать матрицу и сводки парка | Границы категорий PoF/CoF и принадлежность ячейке определены отдельным решением. Обзорная страница парка и матрица установки получают тот же источник, что расчётная карточная матрица, согласно решению RQ03 |
| F21.09 | Перенести `riskRes` и подключить RiskTab | Графики, таблицы, карточки элементов и рекомендации читают один снимок. Проверены пустые/частичные входы и независимые области |

## F22. Карточка фактического технического состояния

Сущность — представление ЕО с источниками, датами актуальности и полнотой показателей. Зависимости — F08–F21, F24–F25. Каждая плитка подключается после готовности своего источника.

| ID | Задача | Критерий приёмки |
| --- | --- | --- |
| F22.01 | Описать состав и источник каждой плитки | У показателя есть владелец, формула/ссылка на расчёт, область, дата и смысл отсутствия. Сводка не становится вторым местом ручного ввода паспорта |
| F22.02 | Реализовать эксплуатацию и состав | Возраст, циклы продления по выполненным ЭПБ, число компонентов/элементов/CML совпадают с первичными данными и учитывают демонтаж |
| F22.03 | Реализовать ресурс, коррозию и износ | Сосуд и каждый змеевик показаны отдельно. Максимумы/минимумы, количество отбракованных элементов и графики имеют источник и базу |
| F22.04 | Реализовать диагностику и предупреждения | Последняя/следующая диагностика, просрочки, аномалии УЗТ/ВИК и ресурс до срока согласованы с соответствующими модулями |
| F22.05 | Реализовать DF, CoF, PoF/RISK и влияние на производительность | Показатели используют сохранённые расчётные версии, выводят устаревание и отсутствующие входы. Производительность использует согласованные параметры установки и паспорта |
| F22.06 | Реализовать эффективное получение сводки | На согласованном большом наборе карточка укладывается в бюджет X11. Сводка не запускает незаметно полную запись новых расчётов |
| F22.07 | Подключить ConditionSummaryTab и переходы к источникам | Из плитки открывается нужная вкладка/элемент. Значение после перехода совпадает с выбранной версией и областью сводки |

## F29. Пропускная способность ППК

Сущности — профиль клапана, параметры истечения, среда/смесь, таблица газов/сжимаемости, расчётный результат. Зависимости — F05, F07–F08, X07.

| ID | Задача | Критерий приёмки |
| --- | --- | --- |
| F29.01 | Описать входы паспорта ППК и контракт результата | Площадь, коэффициенты, P₁/P₂, температура, состав и фаза имеют источники, единицы и допустимость. Нехватка значения возвращает конкретный список |
| F29.02 | Перенести таблицы свойств газов и B₄ | У каждой использованной строки есть версия и источник. Интерполяция, диапазон и отсутствие подходящего газа проверены |
| F29.03 | Перенести свойства газовой и жидкой смеси | MW, плотность, теплофизические параметры и нормирование состава совпадают с эталонами. Неподдержанный компонент не получает выдуманное свойство |
| F29.04 | Перенести газовый расчёт и режимы истечения | Критический/докритический режим, коэффициенты и единицы воспроизводят ядро. Проверены границы перехода и давления |
| F29.05 | Перенести жидкостный расчёт | Условие P₁ > P₂, плотность и α₂ проверены. Неполные или физически неверные входы возвращают блокировку/пояснение по контракту |
| F29.06 | Перенести допустимое давление полного открытия | Кусочные границы давления и единицы проверены на обеих сторонах каждой границы. Принятое значение и предел различимы |
| F29.07 | Реализовать актуальный результат и ход расчёта | Результат содержит версию входов/таблиц, G в кг/ч, среду, режим и шаги. Изменение паспорта обновляет актуальное представление с определённой семантикой сохранённого запуска |
| F29.08 | Подключить ReliefCapacityTab | Для карточки № 13 показаны блокировка, исправление паспорта и новый результат. Другие профили не получают неприменимый расчёт |
