# Доступ, администрирование, аудит и поддержка

Статус F01 — частичная реализация: серверный вход, TOTP, восстановление, профиль и сеансы подключены к React; настройки провайдеров и ограничения описаны в [authentication.md](../authentication.md). Ролевая модель F02 и остальные предметные задачи остаются запланированными. Общие требования определены в [00-foundation.md](00-foundation.md). Полный объём предметных фич приведён в [FEATURES.md](../FEATURES.md).

## F01. Вход и личный кабинет

Сущности — учётная запись, профиль, способ подтверждения, сеанс, запрос восстановления доступа. Предусловия — X01–X05. Фича F02 задаёт членство и полномочия, необходимые для выбора организации после входа.

| ID | Задача | Критерий приёмки |
| --- | --- | --- |
| F01.01 | Описать состояния входа и сеанса, зарегистрировать контракт аутентификации | Frontend различает неверные реквизиты, запрос второго фактора, истечение подтверждения, успешный вход и потерю сеанса |
| F01.02 | Реализовать проверку реквизитов и выдачу сеанса | Неверный пароль не выдаёт доступ. Данные текущего пользователя получаются по действующему сеансу, секреты отсутствуют в ответах |
| F01.03 | Реализовать запрос, проверку и повтор подтверждения | Код/подтверждение ограничены сроком, числом попыток и конкретной попыткой входа. Повтор и два параллельных подтверждения имеют определённый результат |
| F01.04 | Реализовать настройку 2FA и смену способа | Включение завершается после проверки способа. Отключение и смена требуют полномочий текущего пользователя, события отражены в аудите |
| F01.05 | Реализовать выход, список и отзыв сеансов | Отозванный сеанс перестаёт выполнять запросы. «Завершить другие» оставляет действующим только согласованный текущий сеанс |
| F01.06 | Реализовать профиль и смену пароля | Проверяются обязательные поля и текущие реквизиты. Смена пароля применяет согласованную политику отзыва сеансов и фиксирует событие |
| F01.07 | Реализовать восстановление доступа и доставку уведомлений выбранным провайдером | Одноразовая ссылка/операция истекает и не применяется повторно. Сбой доставки виден как отдельное состояние, пароль не заменяется до подтверждения |
| F01.08 | Подключить DemoLogin и AccountSettings к серверным операциям | Полный вход, ошибка кода, повтор, выход и отзыв другого сеанса проходят в браузере. Фиксированные демо-реквизиты относятся к демонстрационному окружению |

## F02. Организации, пользователи и роли

Частично реализовано 06.11.2026: тенанты, платформенное создание/название/статус, членства и provider/subject через CLI, роли owner/admin/member, отдельные БД и настройки входа. Инструкция — [tenancy.md](../tenancy.md). Приглашения, подразделения, полная матрица разрешений и UI управления сотрудниками остаются запланированными.

Сущности — организация, членство, подразделение, роль, разрешение, приглашение, сотрудник платформы. Предусловия — X02–X05 и F01. Управление организацией и рабочие действия внутри неё получают разные разрешения.

| ID | Задача | Критерий приёмки |
| --- | --- | --- |
| F02.01 | Описать права, области действия и статусы организаций/пользователей | Для каждой команды указан субъект и разрешение. Состояния active/trial/suspended и invited/blocked сопоставлены с доступными действиями |
| F02.02 | Реализовать список, карточку, создание и изменение организации | Домен/идентификатор проверяется по согласованной уникальности. Название, статус и метка плана сохраняются и читаются без демо-подстановок |
| F02.03 | Реализовать блокировку и жизненный цикл организации | Блокировка применяется к запросам и фоновым операциям по согласованным правилам. Удаление с зависимыми ЕО, файлами и расчётами имеет явную политику |
| F02.04 | Реализовать членство, подразделения и назначение роли | Пользователь получает права своей организации. Нельзя назначить роль или подразделение из другой организации либо повысить собственные права без разрешения |
| F02.05 | Реализовать приглашение, принятие, повтор и отзыв | Приглашение связано с организацией, адресатом, ролью и сроком. Повтор отправки не создаёт дубли членства, отозванное приглашение не принимается |
| F02.06 | Реализовать пользовательские роли и матрицу разрешений | Изменение прав действует в серверных проверках. Защищённые системные роли и последний необходимый администратор обрабатываются по утверждённой политике |
| F02.07 | Реализовать блокировку пользователя и инициирование восстановления | Блокировка влияет на действующие сеансы. Администратор инициирует восстановление без получения пользовательского пароля |
| F02.08 | Реализовать управление сотрудниками платформы и административный вход в организацию | Полномочия сотрудника платформы ограничены матрицей. Действия при входе в организацию сохраняют реального актора и выбранный контекст |
| F02.09 | Подключить экраны Administration и управления командой | Создание организации, приглашение, принятие, смена роли и блокировка проходят через API с проверкой отказов и межорганизационного доступа |

## F25. История и аудит

Сущности — событие эксплуатации, изменение атрибута, действие безопасности/администрирования. Предусловия — X02–X05. Инфраструктура аудита вводится с первыми командами, подключение источников расширяется вместе с фичами.

| ID | Задача | Критерий приёмки |
| --- | --- | --- |
| F25.01 | Описать виды событий и правила записи | Выполнение диагностики, назначение потока, изменение поля и вход пользователя различаются типом и содержимым. Для каждого события определён владелец |
| F25.02 | Реализовать согласованную запись изменений | Изменение объекта и соответствующий аудит фиксируются атомарно либо через согласованный механизм доставки. Повтор команды не удваивает событие |
| F25.03 | Реализовать чтение истории объекта | Есть сортировка, страницы, фильтры по времени/типу/актору, прежние и новые значения. Скрытые поля и чужие объекты не раскрываются через историю |
| F25.04 | Реализовать журналы организации и платформы | Администратор организации читает свой контекст, сотрудник платформы — разрешённый охват. События административного входа показывают обоих участников |
| F25.05 | Определить хранение, исправления и очистку | Записи имеют серверное время и устойчивые ссылки. Исправление предметного события сохраняет факт исправления. Удаление объектов следует политике сохранения истории |
| F25.06 | Подключить вкладку «История» и журналы каталогов/администрирования | В сценарии изменения паспорта, каталога и роли показан реальный автор. Производные демо-события не дублируют импортированные факты |

## F27. Помощь и поддержка

Сущности — статья, категория, обращение, сообщение, внутренняя заметка, назначение и уведомление. Предусловия — F01–F02, F25. Вложения используют F24, если их включение будет подтверждено в контракте обращения.

| ID | Задача | Критерий приёмки |
| --- | --- | --- |
| F27.01 | Подготовить каталог статей и поиск | Статьи имеют категорию, заголовок, содержание и дату обновления. Поиск и открытие статьи доступны разрешённым пользователям |
| F27.02 | Реализовать создание и список обращений | Обязательные поля, категория и приоритет валидируются. Автор видит свои обращения, доступ к обращениям коллег определяется матрицей |
| F27.03 | Реализовать переписку и внутренние заметки | Сообщения упорядочены и защищены от дублей при повторе. Клиентский ответ не содержит служебных заметок поддержки |
| F27.04 | Реализовать назначения и переходы статуса | Разрешённые роли меняют исполнителя и статус. Параллельные назначения обнаруживают конфликт, история переходов сохраняется |
| F27.05 | Реализовать уведомления и повтор доставки | Создание/ответ/смена статуса формируют согласованные уведомления. Ошибка доставки допускает безопасный повтор без повторного сообщения в обращении |
| F27.06 | Подключить HelpPage и административную обработку обращений | Пользователь создаёт обращение, поддержка отвечает, пользователь читает ответ. Проверены разграничение организаций и скрытость заметок |
