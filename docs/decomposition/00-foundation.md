# Общие задачи backend

Рабочая декомпозиция от 06.11.2026. Задачи `X01`–`X12` используются всеми фичами. Статус каждой задачи — запланирована. Сроки и исполнители назначаются после уточнения объёма и оценки.

За исходный архитектурный контекст принят [существующий план](../architecture.md). Конкретные версии технологий, провайдеры и механизм очереди требуют проверки при начале реализации.

| ID | Задача | Проверяемый результат |
| --- | --- | --- |
| X01 | Подготовить запускаемый backend, конфигурацию окружений и подключение к БД | Разработчик поднимает сервис по инструкции, выполняет миграции и проверяет доступность. Секреты задаются окружением |
| X02 | Реализовать контекст организации и проверку принадлежности связанных объектов | Два тестовых тенанта изолированы в чтении, записи, фоновой задаче и выдаче файлов. Подмена ID связанного объекта отклоняется |
| X03 | Утвердить соглашения API | Описаны форматы ID, дат, времени, десятичных чисел, единиц, манометрического/абсолютного давления, пустого значения, пагинации, ошибок полей, запрета доступа и конфликта версии. Примеры согласованы с frontend |
| X04 | Определить границы транзакций, версию изменяемых объектов и повтор команд | Для каждой команды описаны атомарность, ключ/семантика повтора и конфликт. Повтор после тайм-аута не создаёт дубль и не теряет подтверждённую запись |
| X05 | Подготовить запись предметных событий и аудита | Изменение и его событие согласованы по транзакции. Автор, организация и серверное время восстанавливаются для принятой команды |
| X06 | Подготовить версионирование справочников и переопределений | Можно получить действующее значение, его источник и конкретную историческую версию. Обновление базового набора сохраняет согласованные пользовательские изменения |
| X07 | Подготовить единый контракт расчётного запуска | Входы, версия ядра, версии справочников, актор, время и результат связаны неизменяемым снимком. Полученный результат воспроизводится по снимку |
| X08 | Подготовить выполнение длительных операций и выдачу результата | У операции есть ID, состояния ожидания/выполнения/успеха/ошибки, ограничение доступа и определённое поведение повтора. Результат незавершённого запуска не показывается как готовый |
| X09 | Подготовить сопоставление и импорт старых данных | Формат исходника, версия миграции и таблица старых/новых ID фиксируются. Есть предварительный отчёт и повтор без дублей. Политика конфликтов задаётся явно |
| X10 | Подготовить frontend-адаптер и контролируемые ответы для Storybook | Приложение обрабатывает загрузку, отсутствие данных, ошибки и конфликт. Истории воспроизводят те же контракты данных |
| X11 | Согласовать профиль нагрузки и наблюдаемость | Зафиксированы объёмы ЕО, элементов, CML, дат, пользователей и размеры файлов, бюджеты ответов и расчётов. Измерение показывает запросы, время и ошибки с ID операции |
| X12 | Собрать проверки совместимости и воспроизводимости | Проверяются права, конкуренция, повтор команды, миграция и численные эталоны. Известные расхождения с Excel учитывают `spec/EXCEL_ERRORS.md` |

## Правила готовности задачи фичи

Задача считается завершённой после реализации контракта, проверок предметных ограничений и доступа, необходимого аудита и подключения к обычному пользовательскому сценарию. Для изменения данных дополнительно проверяются повтор и конфликт. Для расчёта — численный эталон, неполные входы и происхождение результата.

Окончательные имена таблиц и маршрутов определяются при проектировании конкретной задачи. Сущности в следующих документах обозначают предметную модель и границы операций.
