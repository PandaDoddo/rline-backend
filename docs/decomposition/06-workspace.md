# Реестр, обмен данными и методические сценарии

Статус всех задач — запланированы. Общие требования определены в [00-foundation.md](00-foundation.md). Сводки подключают реальные показатели по мере готовности их источников.

## F23. Реестр, сводки парка и поиск

Сущности — запрос реестра, фильтр, сортировка, набор результатов, показатель, поисковый результат и выбранный диапазон. Зависимости — F01–F03, F08. Диагностика/ресурс/риски добавляют F12, F14, F18–F21.

| ID | Задача | Критерий приёмки |
| --- | --- | --- |
| F23.01 | Описать колонки и источники показателей | Для каждой колонки известны поле паспорта/вычисление, единица, тип сортировки, доступность и смысл пустого значения |
| F23.02 | Реализовать фильтры, дерево размещения и поиск в реестре | Условия совпадают с текущими операторами frontend и применяются ко всему доступному набору. Количество результатов соответствует фильтру |
| F23.03 | Реализовать устойчивую пагинацию и выбор колонок | Равные значения имеют порядок по ID, параметры следующей страницы проверяются. Семантика при изменении данных определена решением WQ01 |
| F23.04 | Реализовать диагностические, ресурсные и расчётные колонки | Значения и предупреждения совпадают с карточкой и областью сосуда/змеевика. Устаревший результат отмечен, пустой результат не генерируется |
| F23.05 | Реализовать выбор строк и копирование диапазона | Выделение относится к ID/позициям согласованного набора, а не только DOM. Копирование диапазона за пределами загруженных страниц возвращает нужный порядок и количество ячеек |
| F23.06 | Реализовать агрегаты и списки приоритетов по парку | Матрица риска и сводка толщины используют реальные источники F14/F21. Проверены частично рассчитанный парк и разные даты актуальности |
| F23.07 | Реализовать глобальный поиск с переходом к сущности | Найдены доступные ЕО и согласованные виды объектов. Результат содержит стабильную ссылку и не раскрывает чужие названия через подсказки |
| F23.08 | Реализовать оптимизацию выборок и индексов | На наборе X11 измерены сортировки, сложные фильтры, групповые показатели и страницы. Стоимость выдачи не растёт из-за полного пересчёта каждого паспорта при каждом вводе |
| F23.09 | Подключить реестр, поиск и обе обзорные страницы | Сохранены открытие карточки, виртуальное окно, фильтры и копирование. `genRisk`/`buildThickness` заменены соответствующими реальными источниками в рабочем режиме |

## F26. Импорт, экспорт, снимки и рабочие виды

Сущности — формат и версия переноса, пакет импорта, сопоставление ID, операция экспорта, файл результата, пользовательский вид. Зависимости — X08–X10, F01–F02, F24–F25 и контракты импортируемых сущностей.

| ID | Задача | Критерий приёмки |
| --- | --- | --- |
| F26.01 | Инвентаризировать сохраняемое состояние frontend | Каждое поле `rline.state.v1` и `ui.*` отнесено к предметным данным, настройкам, черновику, кэшу или демо. Для сохраняемых данных указан целевой владелец |
| F26.02 | Определить формат и версии импорта | Схема допускает прежние наборы через явные миграции. Неподдержанная версия/поле возвращает диагностический отчёт |
| F26.03 | Реализовать предварительный разбор и сопоставление ID | Проверяются ссылки, типы, дубли, единицы и права. До подтверждения виден план создать/обновить/пропустить/конфликт |
| F26.04 | Реализовать применение и повтор импорта | Граница транзакции/пакетов и восстановление после сбоя заданы явно. Повтор не удваивает ЕО, этапы, CML и события, конфликт не теряет рабочие данные |
| F26.05 | Реализовать перенос файлов и результатов расчётов | Содержимое, метаданные и legacy-расчёты различимы. Импорт без полных версий входов не выдаёт результат за воспроизводимый актуальный |
| F26.06 | Реализовать сохранённые пользовательские виды | Колонки, порядок, фильтры, сортировка и плотность привязаны к пользователю и области. Удалённое поле старого вида обрабатывается с объяснением |
| F26.07 | Реализовать задания экспорта по фильтру и выбранным строкам | Зафиксированы набор, права, параметры и момент данных. После завершения получатель получает фактически созданный файл или ошибку |
| F26.08 | Реализовать XLSX и согласованные дополнительные форматы | Заголовки, единицы, даты, пустые значения и порядок совпадают с контрактом. Текстовые значения безопасно записываются как данные, количество строк проверено |
| F26.09 | Разделить перенос рабочего набора, резервирование и восстановление | Определены область, роль и способ подтверждения каждой операции. Восстановление не заменяет данные другой организации и имеет процедуру возврата после сбоя |
| F26.10 | Подключить диалоги экспорта, снимки и настройку вида | Вместо уведомления-заглушки скачивается файл. Ошибка хранения/обрыва сети сохраняет данные и возможность безопасного повтора |

## F28. DIFF и методические эксперименты

Сущности — экспериментальная методика, версия, исходный сценарий, результат, сравнение и решение о применении. Зависимости — F07, X07 и ядра, с которыми ведётся сравнение. Утверждение экспериментальной методики является отдельным предметным решением.

| ID | Задача | Критерий приёмки |
| --- | --- | --- |
| F28.01 | Инвентаризировать вкладки DIFF и их вычисления | Для H₂S, сульфидно-щелочной коррозии, ClSCC, цианидов и PASCC описаны входы, сравниваемые варианты, источник и текущий статус обсуждения |
| F28.02 | Зафиксировать границу экспериментального использования | Потребитель явно получает экспериментальную метку и версию. Сценарий не заменяет принятый DF/RISK без отдельного решения |
| F28.03 | Реализовать хранение/выполнение сценария, требующего сервера | Выбранные входы, версии вариантов и результаты воспроизводятся после повторного открытия. Чисто интерфейсные пояснения получают обычный контракт чтения |
| F28.04 | Реализовать сравнительный результат | Разница значений связана с конкретной формулой, входом и версией. Неподдержанный диапазон отражён явно |
| F28.05 | Реализовать решение о переносе методики в рабочее ядро | Есть утверждённое основание, эталоны и новая версия соответствующего ядра F18/F21. Сохранённые расчёты прежней версии доступны |
| F28.06 | Подключить DiffPage и разграничить доступ | Пользователь открывает сценарий и сравнение, видит статус методики. Права на изменение эксперимента и утверждение разделены |
