# Оборудование, потоки и документы

Статус всех задач — запланированы. Общие требования определены в [00-foundation.md](00-foundation.md). Правила паспорта и устойчивых ID сверяются с [AGENTS.md](https://github.com/PandaDoddo/rline/blob/main/AGENTS.md).

## F08. ЕО и паспорт

Сущности — ЕО, тип, профиль, значение паспортного атрибута, отметка проверки и версия. Зависимости — F01–F03, профильные справочники F07 и аудит F25.

| ID | Задача | Критерий приёмки |
| --- | --- | --- |
| F08.01 | Сопоставить все поля профилей карточек с предметной моделью | Для каждого поля известны единица, тип, пустота, применимость и источник. Одинаковые подписи в разных блоках имеют разные устойчивые ключи |
| F08.02 | Реализовать создание ЕО | Сохраняются введённые значения, выбранное размещение и профиль. Новая карточка получает устойчивый ID и остаётся пустой в незаполненных полях |
| F08.03 | Реализовать чтение эффективного паспорта | Значения читаются из паспорта с учётом разрешённых авторасчётов. Реестровые и демо-значения не заполняют пустые поля после миграции |
| F08.04 | Реализовать сохранение и отмену черновика | Атомарно сохраняется согласованный набор изменений. Уход со страницы поддерживает сохранить/отменить/остаться. Конфликт версии оставляет черновик доступным |
| F08.05 | Реализовать профильную валидацию и применимость полей | Изменение НТД учитывает эффективный профиль и группу сосуда. Условия, не применимые к ЕО, не попадают в расчёт как заполненный вход |
| F08.06 | Реализовать паспортные даты и отметки проверки | Дата из одного года сохраняет признак «уточнить». Проверка хранит автора/время и согласованно меняется после правки значения |
| F08.07 | Определить смену профиля, перемещение, архивирование и удаление ЕО | Зависимые компоненты, диагностики, файлы и расчётные снимки обрабатываются по политике. Смена профиля не молча отбрасывает сохранённые данные |
| F08.08 | Перенести `cardOv` и привязанные идентификационные данные | Учтён однократный перенос `__regMig`, техпозиции УПННГ и дата по году. Повтор миграции сохраняет пользовательские изменения |
| F08.09 | Подключить PassportTab, форму создания и чтение в реестре | Один набор значений виден в карточке и списке после повторного входа. Наименование и регномер отображаются с правилами проекта |

## F09. Компоненты, элементы, соединения и трубный пучок

Сущности — компонент, сегмент/элемент, соединение, сборка, сосуд, отдельный змеевик, трубный пучок. Зависимости — F08, F04, F07 и F25.

| ID | Задача | Критерий приёмки |
| --- | --- | --- |
| F09.01 | Описать структуру типов компонентов и устойчивые ID | ID независим от позиции. Компонент, пояс, сегмент, элемент сборки и отдельный змеевик имеют однозначного владельца и тип |
| F09.02 | Реализовать создание и правку компонентов и сегментов | Геометрия, материал, номинальная толщина и профильные поля валидируются. Нумерация для отображения отделена от ID |
| F09.03 | Реализовать соединения и порядок конструкции | Соединение ссылается на существующий допустимый компонент/элемент той же ЕО. Порядок отображения воспроизводится после сохранения |
| F09.04 | Реализовать демонтаж, восстановление и удаление | Демонтаж не переносит CML и историю на другой элемент. Восстановленный компонент сохраняет ID. Удаление объекта с измерениями имеет явное правило |
| F09.05 | Реализовать сосуд и независимые змеевики | Каждому змеевику назначена отдельная область расчёта. Сводка сосуда исключает змеевики там, где этого требуют правила |
| F09.06 | Реализовать состав и специальные атрибуты трубного пучка | Данные пучка, материалы, геометрия и сегменты сохраняются согласованно с составом ЕО. Условия применимости вкладки совпадают с профилем |
| F09.07 | Реализовать атрибуты элемента для расчётов | Термическая история, классификаторы и другие профильные входы доступны расчётам по конкретному элементу. Отсутствие источника показывается явно |
| F09.08 | Перенести `compData`, `compChk` и `tbData` | Сохранены старые ссылки и выполненные миграции ID, включая исторические перестановки компонентов. Дубли миграций не меняют принадлежность измерений |
| F09.09 | Подключить ComponentsTab, редакторы и TubeBundleTab | Добавление, связь, демонтаж и восстановление проверены вместе с сохранением/отменой карточки и открытием старых измерений |

## F10. Потоки установки и состав среды

Срез 08.11.2026: F10.01–05 и F10.08 подключены в базовом объёме: дерево, опросник с комментариями, карточка, каталогизированный состав, конверсия базы, свойства/критерии смеси и неизменяемые снимки. F10.06–07, импорт F10.09 и назначения F11 остаются в работе. Границы и проверки — [process-flows.md](../process-flows.md).

Сущности — дерево потоков, поток, компонент состава, примесь, параметр среды, ремонтный процесс, результат свойств смеси. Зависимости — F03, F05, F07. Скрининг задаётся совместно с F17, без дублирования владельца правил.

| ID | Задача | Критерий приёмки |
| --- | --- | --- |
| F10.01 | Описать дерево технологических, альтернативных, вспомогательных и наружных потоков | Узлы и листья имеют устойчивые ID. Виды потоков, ремонтные процессы и связи с установкой сохранены |
| F10.02 | Реализовать первичное наполнение и правку структуры | Каждый вопрос первичного наполнения имеет ответ и комментарий. Создание дерева атомарно, повтор команды не создаёт вторую структуру |
| F10.03 | Реализовать карточку потока и черновик | Температура, давление, фаза, pH и прочие поля валидируются с единицами. Отмена и переход между потоками сохраняют согласованную семантику |
| F10.04 | Реализовать состав и пересчёт массовой/мольной базы | Вещества связаны с каталогом по ID, учитываются MW и признак «и выше». Примеси/справочные строки отделены от компонентов расчёта. Неполные MW и суммы обрабатываются явно |
| F10.05 | Реализовать свойства и критерии опасности смеси | MW/NBP/плотность и суммы по flammable/toxic/nfnt/inert имеют прозрачные входы. Один компонент может входить в несколько критериев |
| F10.06 | Реализовать подбор репрезентативной среды и токсичных компонентов | Воспроизводятся условия нормирования, консервативности, IDLH, инертных и ароматических компонентов из правил проекта. Ручной выбор изменяется только явным применением |
| F10.07 | Реализовать параметры для определения МД | Вопросы, ответы, комментарии, пороги и зоны внимания сохраняются отдельно от описания потока. Неизвестное значение не подменяется отрицательным |
| F10.08 | Реализовать пересчёт и предупреждение об изменении состава | Сигнатура входов выявляет устаревшие свойства. Пользователь видит, какие расчётные значения изменятся, и подтверждает применение по согласованному сценарию |
| F10.09 | Импортировать `flowModels`/`flowHist` и подключить ProcessFlowsPage | Сохраняются дерево, базы состава, результаты свойств и история. Несуществующие вещества и неперенесённые поля включены в отчёт |

## F11. Назначение потоков оборудованию

Срез 08.11.2026: базовые назначения, стороны, пространства/пучок, независимые змеевики, наследование и доли процентов года подключены к карточке ЕО. Проверки/версии, агрегатный аудит и обнаружение изменения потока реализованы; временные периоды, полный журнал, массовая замена, импорт и зависимые расчётные снимки остаются в работе. Подробности — [equipment-flow-contacts.md](../equipment-flow-contacts.md).

Сущности — назначение потока, область контакта, сторона, период/доля режима и история назначения. Зависимости — F08–F10, F25. Расчётное использование назначений уточняется отдельно для каждого ядра.

| ID | Задача | Критерий приёмки |
| --- | --- | --- |
| F11.01 | Описать внутренний и наружный контакт, наследование и режимы | Для ЕО/компонента/элемента определено эффективное назначение. Внутренняя среда, наружная среда, обогрев и изоляция различимы |
| F11.02 | Реализовать назначение, замену и снятие потока | Ссылки относятся к доступной установке и ЕО. Противоречивый контакт либо запрещён, либо выдаёт согласованное предупреждение |
| F11.03 | Реализовать контакт для трубного/межтрубного пространства и змеевиков | Разные области получают самостоятельные назначения. Поток змеевика не становится автоматически потоком сосуда |
| F11.04 | Реализовать долю времени работы и параметры режима | Периоды/доли хранятся с единицами и проверками. Ядро получает список режимов и применяет свою утверждённую агрегацию |
| F11.05 | Реализовать историю и влияние изменений | Назначение отражено в журнале. Изменение делает зависимые МД и расчёты устаревшими без изменения сохранённого снимка |
| F11.06 | Перенести `eqFlow`/`efUnit` и подключить FlowsTab | Назначения читаются по устойчивым ID после демонтажа/восстановления компонента. Пустые фактические назначения остаются явно незаполненными |

## F24. Документы ЕО

Сущности — файл, загрузка, реквизиты документа, связь с ЕО и состояние удаления. Зависимости — F01–F02, F08, F25 и X08. Версионирование файла включается после решения EQ05.

| ID | Задача | Критерий приёмки |
| --- | --- | --- |
| F24.01 | Описать типы документов, реквизиты, размеры и доступ | Указаны обязательные поля, допустимые типы/размеры и роли. Наличие метаданных без содержимого отображается отдельным состоянием |
| F24.02 | Реализовать начало, завершение и отмену загрузки | Повтор и обрыв загрузки не создают доступный неполный файл. Проверяются размер, разрешённое содержимое и принадлежность загрузки |
| F24.03 | Реализовать атомарную привязку документа к ЕО | Файл и реквизиты доступны после успешного завершения. Отмена черновика не оставляет документ в карточке, неиспользуемые загрузки очищаются по политике |
| F24.04 | Реализовать список, чтение и скачивание | Проверка доступа выполняется при выдаче содержимого. Срок действия ссылки и поведение отзыва доступа определены |
| F24.05 | Реализовать изменение реквизитов и удаление | Политика версий/замены согласована. Удаление файла и связи согласовано, аудит сохраняет факт операции |
| F24.06 | Перенести `docAdd` и локальные файлы | Содержимое и только метаданные различимы. Сгенерированный демо-документ не импортируется как реально существующий файл без явного решения |
| F24.07 | Подключить DocumentsTab и форму добавления | Загрузка, отмена, ошибка размера, повтор, скачивание и удаление проверены через интерфейс и после нового сеанса |
