# Каталог механизмов деградации: серверный контур

Срез 07.11.2026. 71 карточка из исходных `corrdm.js` и `dmcat_a/b/c.js` перенесена в версионированный набор `resources/catalogs/damage-mechanisms.json`. UUID зависит от устойчивого исходного кода, а не от позиции. Сохранены исходные метаданные, рабочие пересказы, связанные механизмы и коррозионно-активные компоненты. Дополнения и исключения групп материалов применены в исходном порядке. Полные тексты API 571 не импортируются; отдельные поля допускают собственный текст пользователя в tenant-БД.

## API и данные

- `GET /api/damage-mechanisms/schema` — типы полей, группы и разделы.
- `GET /api/damage-mechanisms` — постраничный список без текстов карточек; q, status, mode=571/581/corrosion/cracking/fatigue/embrittlement, materials[]. Выбор материалов означает совпадение хотя бы с одной выбранной группой.
- `GET /api/damage-mechanisms/{uuid}` — карточка и краткие связанные записи в согласованном снимке REPEATABLE READ.
- `PATCH /api/damage-mechanisms/{uuid}` — правки, reset_fields, sources/verification и обратимый архив. Обязательная версия; при конфликте 409. Owner/admin изменяют, member читает.
- `GET /api/damage-mechanisms/{uuid}/events` — последние 200 сохранений по 30 на страницу, с именем автора из профиля организации и изменёнными полями. Полный аудит остаётся в БД; профиль постороннего пользователя не раскрывается.

Пункт/страница стандарта, исходные дополнения, связи и справочные коррозионные компоненты недоступны на запись. Разрешены наименование, обозначение, вид, справочная связь DF, подверженные группы материалов и тексты разделов. Новый механизм вручную не создаётся: эта задача остаётся отложенной в основном BACKLOG. Справочная связь DF не означает, что серверный скрининг уже реализован.

Общие `CatalogRecords`, `CatalogHistory` и `CatalogValues` обеспечивают транзакцию/версию/аудит, проверку только заполненных свойств и различение 0/false/null. Представление одного числа целым/дробным и порядок ключей JSON-объекта сохраняют действующую проверку. Изменение значения или источника снимает её; автора/время назначает сервер. Повтор seed не переписывает tenant-правки, проверки или архив.

## React и Storybook

`features/damage-mechanisms` сохраняет DamageMechanismsPage, виртуальные плитки, rus/origin, разделы, материалы и связанные карточки. Добавлены редактируемые группы, архив, источники/проверки, reset, 409 и защита черновика. В API-режиме демонстрационные dmCards не загружаются. `useApiSnapshot` отменяет устаревшие запросы; отдельная история проверяет поздний ответ поиска. Общая CatalogSourcePanel обслуживает вещества, марки и механизмы; служебные автор/время не попадают в запрос редактирования.

Сервисы данных привязаны к тенанту при открытии раздела. Смена организации во время подготовки CSRF блокирует старую запись; позднее чтение не передаёт данные в новую организацию. Escape обрабатывается в рабочей области с учётом внешних окон и подтверждения несохранённых правок.

## Проверки и границы

`DamageMechanismsTest`: 71 запись, фильтры, целостные ссылки, разделение тенантов и собственного текста, версии/reset, роли, архив, предел истории и имена авторов. `CatalogValuesTest`: эквивалентные числа и различие пустоты/0/false. `npm run test:mechanisms` и `npm run test:mechanisms:browser`: нормализация, материалы, языки/собственный текст, виртуализация, связанные переходы, черновик/409, поздний ответ, пусто/ошибка. На testing catalogs-20261107-13 проверены реальные чтение/поиск, русские/английские разделы и отмена черновика без загрузки демо-чанков. Базовые карточки этой проверкой не изменялись.

Остаются: явный импорт dmOv с предпросмотром, публикация обновлений набора, серверный скрининг ЕО и зависимые расчётные снимки. Эти задачи не считаются завершёнными наличием каталога.
