# Local: вход по логину и паролю

По запросу пользователя 07.11.2026 для локального тенанта `rline` включён режим входа без TOTP. В `auth_config.local` сохранено `require_totp=false`. Реквизиты учётной записи не менялись, сохранённые TOTP-секреты пользователей не удалялись.

На testing опубликована сборка `password-only-20261107-01`, учитывающая `user.two_factor_required` из `/auth/me`. После обновления страницы можно войти по обычным e-mail и паролю без настройки приложения-аутентификатора. Старые сборки frontend, не учитывающие новую политику, нужно обновить/продвинуть отдельно.

## Изменение политики

В настройках организации → провайдер Local доступна галочка **«Требовать TOTP при локальном входе»**. Снята — только пароль; установлена — Local + TOTP с обязательным подключением. Изменять политику могут владелец/администратор организации либо администратор платформы согласно существующим правам. Изменение увеличивает auth_version и завершает прежние сеансы организации.

API принимает частичную конфигурацию:

```json
{"providers":{"local":{"require_totp":false}}}
```

Командная настройка выполняется через существующую `tenant:auth-config` с JSON-файлом; в файле для CLI нужен объект `{"local":{"require_totp":false}}` без внешнего providers.

По умолчанию и у новых тенантов `require_totp=true`. LDAP/AD продолжают требовать TOTP; Multifactor использует внешний механизм подтверждения. Переданный при входе параметр require_totp не меняет серверную политику.

Проверены правильный/неправильный пароль, защищённые API без enrollment, обязательность MFA по умолчанию, независимость двух тенантов и сохранность общего секрета TOTP. Реальный вход существующей локальной учётной записи и GET /api/installations также прошли; проверочный сеанс завершён.
