# Первичное наполнение локального тенанта

Модуль `DataExchange` принимает `rline-dataset-v1`. Формат содержит иерархию, установки, паспорта ЕО, компоненты, диагностики, CML, точки и параметры пространств. Это пока не полный обмен всеми разделами: дерево/карточки потоков, их состав/скрининг, выбранные потоки/физические контакты и правки базовых веществ уже поддержаны; затраты установки также поддержаны (installations[].costs); анкета и обслуживание установки также поддержаны; остальные справочники и сохранённые RBI-запуски ещё требуют адаптеров.

Записи выполняются через те же `FacilityCommands`, `EquipmentCommands` и правила, что HTTP API. Импорт — одна транзакция; ошибка последней ЕО отменяет предыдущие записи. Проверки old не становятся проверками текущего пользователя. Исходные проверки сохраняются только как свидетельство.

## Пробный запуск

```sh
php artisan dataset:import build/old-demo-manifest.json --tenant=rline --actor=1
```

Без `--apply` выполняются настоящие предметные команды с последующим откатом. Это позволяет проверить FK и бизнес-правила, а не только структуру JSON. Использовать идентификатор действующего администратора/владельца выбранного тенанта. Участник другой организации выполнить импорт не может.

После проверки отчёта `--apply` сохраняет набор. `--allow-source-issues` дополнительно разрешает импорт набора, где исходные ошибки явно вынесены в отчёт. Этот параметр не отключает валидацию предметных данных. Например, отрицательное давление из old сохраняется в свидетельстве ошибки, а каноническое поле остаётся неизвестным.

Первичное наполнение допускается только без существующих ЕО. Повтор точно такого же набора возвращает неизменяемую квитанцию по SHA-256; он не перезаписывает более поздние правки. Обновление отличающегося набора поверх существующих ЕО требует отдельного механизма сверки и пока не реализовано.

На 10.11.2026 полный preview с потоками/контактами прошёл: 241 ЕО, 3323 компонента, 2559 CML, 854 этапа, 8590 рядов/35969 точек, 79 узлов потоков, 210 строк состава, 22 выбранных потока, 248 контактов, 287 связей. Отдельный preview 62 правок каталога + всех потоков + четырёх ЕО прошёл. Транзакции отменены; рабочий rline не заполнен. Локальные миграции до 000055. Продолжение — docs/RESUME.md основного репозитория.

## Происхождение значений

- `stored_snapshot` — сохранённые исходные значения; `demo_expanded` — явно обозначенный демонстрационный набор.
- Генерация разрешена только в `demo_expanded`. Отдельно отмечаются поля паспорта, параметры компонентов/пространств, схемы CML и точки.
- Таблицы `dataset_import_*_origins` содержат неизменяемое свидетельство исходного скалярного значения с FK на конкретного владельца. Редактируемые предметные данные остаются в нормализованных таблицах.
- Текущая отметка генерации показывается, пока значение совпадает с импортированным. Ручная правка сохраняет свидетельство, но снимает текущую отметку. Возврат к тому же исходному значению снова показывает его происхождение.
- API отдаёт `data_origin` и `thickness.stages[].measurements[].point_origins`. Эти поля доступны только для чтения и не отправляются формой обратно в PATCH.
- В карточке есть общий баннер. Поля паспорта/пространств и параметры компонента помечаются; сгенерированные точки и сводки с ними выделены жёлтым. CSV сохраняет эти отметки и различает ноль и незамеренную точку.

JSON в квитанции — неизменяемый исходный документ и отчёт, а не рабочая модель паспорта или измерений. UPDATE/DELETE свидетельств запрещены на уровне PostgreSQL. Составные FK исключают привязку свидетельства к объекту другой ЕО.

## Подготовка old

В `frontend/tools/legacy-parity` адаптеры работают только с доверенной локальной копией old, без пользовательского JS и сетевого доступа. `preview-demo-inputs.mjs` разворачивает демопредставления; `build-demo-manifest.mjs` собирает манифест. Используются зафиксированные SHA-256 исходных файлов. Изменение old требует повторного предпросмотра.

Позиционный CML АВО сопоставляется через фактический корневой компонент. Флаг `sep` у old может обозначать настоящий змеевик; такой компонент не исключается. Явные неизвестные/пустые значения не заменяются демозначениями. Неразрешённые исходные ссылки и пропуски сохраняются в отчёте, без назначения другому физическому элементу.

## Вещества и контакты (10.11)

Правки базовых веществ принимаются по существующему code только при неизменённой исходной записи; предварительная пользовательская правка даёт конфликт, а не перезапись. Значения валидируются общим SubstanceInputValidation. Неизменяемые квитанции dataset_import_substances и dataset_import_flows показывают происхождение и более поздние правки через data_origin.

flow_selection — упорядоченный независимый список доступных потоков. Он не означает контакт оборудования со всеми выбранными средами. Фактические контакты ссылаются на физических владельцев, стороны и пространства. Явно пустая связь не превращается в наследование. Проверки source chk остаются свидетельством; текущие verified=false. История jr2 пока не материализуется как журнал текущих операций.

Манифест old-full-demo-v4 дополнительно включает восемь параметров затрат КС-2. Это следующая версия после полного успешного preview v3 (241 ЕО); не смешивать результаты проверки версий. Проверка v4 на нормализованной схеме затрат выполняется отдельным preview с откатом.

## Полный preview и замечания установки (10.11)

Preview теперь записывает также квитанции/замечания/аудит и выполняет SET CONSTRAINTS ALL IMMEDIATE до отката. До этого исправления v3/v4/v5 проверяли предметные записи, но не полный финальный граф отложенных FK/ограничений. Поднабор v6 прошёл; полный v6 выполняется отдельно, см. docs/RESUME.md.

installations[].source_id — устойчивый ключ исходного снимка (по умолчанию UUID записи). Квитанции dataset_import_installations неизменяемы. issues[].installation_source_id ссылается на объявленную установку; замечание может иметь только одного владельца. Для анкеты API отдаёт data_origin, source_issues и source_issues_truncated, только в пределах текущего владельца/тенанта. Старые NA без обоснований не становятся принятыми ответами.

### Проверенный preview и обслуживание (10.11.2026)

Preview теперь записывает весь граф, включая квитанции/замечания/аудит, и выполняет SET CONSTRAINTS ALL IMMEDIATE перед откатом. Раньше он завершался до финальных квитанций; старые previews не подтверждали эти ограничения. Полный v6 (241 ЕО, 767 замечаний/20 исходных ошибок, затраты/анкета) успешно проверен исправленным preview. Миграции локального rline применены до 62.

installations[].maintenance.records — список id/kind/values/source_reference/source_verified; no_stops опционален. Источник не может передать verified/unlock. Каждая запись получает неизменяемую квитанцию, связанную с установкой и пакетом; текущая проверка остаётся пустой. Версия установки учитывает все последовательные команды, версия записи отслеживает последующие правки. Подробности — installation-maintenance.md. v7 добавляет 5 записей обслуживания; subset 4 ЕО со всем связанным графом прошёл с откатом. Рабочий rline ещё не заполнен.

### Независимое чтение и критерии RBI

Свежие preview/apply выполняют DatasetReadback: паспорт/квалификаторы, принадлежность ЕО, CML, координаты/порядок/количество точек, ноль и явные пропуски; данные установки, затраты, анкета, обслуживание и overrides критериев. Проверка использует новые модели/SQL-проекции, которые читает API, а не объекты команд записи. Числовой roundtrip допускает абсолютную погрешность до 1e-10 только между ненулевыми числами; строки, null, bool и ноль не приводятся друг к другу. Любое расхождение откатывает всё. Квитанции и аудит создаются в той же транзакции; отложенные ограничения проверяются до успешного завершения.

verification в ответе относится к свежему запуску; replay возвращает неизменяемую квитанцию, без заявления, что ручные правки повторно совпали с первоначальным входом. Полный v7 проверил 241 ЕО, 72890 значений паспорта/толщин, включая 35969 точек. v8 subset проверил также 569 значений установки. Это ещё не полная независимая сверка всех полей компонентов/потоков и расчётных результатов.

installations[].risk_criteria содержит schema_version и values; использует те же правила/команду, что API. Сохранённые старые интервалы в годах не смешиваются с наследованием МРИ в месяцах. Подробнее risk-criteria.md. Локальная схема до 63; манифест v8 добавляет 12 критериев ks2, рабочее наполнение ещё не выполнено.

## Визуальные наблюдения (000064)

Поддержан equipment[].visual_inspections с привязкой к физическим элементам и выполненным диагностикам. Формат и правила — docs/visual-inspections.md. old-full-demo-v9 содержит 28 сохранённых строк; текущие проверки не заимствуются из old. Preview включает независимое обратное чтение, проверяет полный граф и откатывает его целиком.
