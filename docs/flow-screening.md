# Первичный скрининг МД потока

Срез 09.11.2026: F10.07 и базовые F17.01–03 подключены к Laravel/PostgreSQL и React-карточке потока. Это первичный фильтр среды, **не итоговая применимость механизма к оборудованию**: материал, температура и условия элементов рассматриваются отдельно.

## Данные и правила

Первоначальная 000015 вводила JSONB screening; 000025 переносит его в типизированные process_flow_environments, отдельные комментарии и числовые границы/зоны с FK на определения вопросов. Старые карточки остаются пустыми; демо-ответы не подставляются. Раздел доступен только для fluid-потоков категорий main/alternative/auxiliary. Для групп, наружных и ремонтных потоков запись отклоняется.

pH имеет один источник — process_flow_properties.ph. Поле screening.values.ph сохранено как совместимый DTO-псевдоним, а оба редактора синхронизированы. Одновременные противоречивые значения отклоняются; перенос разных старых pH останавливается с полным откатом. Если pH был только в старом screening, он переносится с явной отметкой происхождения и исходными автором/временем. Неизвестный null и измеренный ноль различаются. Пустой ввод не создаёт числовой ноль и не добавляет отсутствующий ключ свойства.

Версионированная база resources/catalogs/flow-screening.json содержит 29 параметров, 32 механизма/88 вопросов, включая 21 механизм первичного скрининга. Она явно перенесена из существующих правил frontend mdscr.js, без новых предметных допущений и без подтверждения соответствия полному стандарту. tools/export-screening-baseline.mjs воспроизводит экспорт (запуск из backend при наличии соседнего frontend); при изменении правил менять версию базы. На runtime frontend не исполняет расчётное ядро.

Состояние хранит sparse values (boolean/number, null сбрасывает к неизвестному), comments (у каждого параметра и вопроса) и thresholds (ключ механизм|номер вопроса; threshold/near — массивы чисел, null сбрасывает переопределение). Временные метки и автор проставляются сервером. Диапазон требует две упорядоченные границы; зона внимания неотрицательная, для границ может различаться. Одиночная зона применяется к обеим границам, пустой массив отключает её.

- Активный: все условия среды выполнены. Неизвестное или зона внимания дают потенциальный статус. Хотя бы одно отрицательное условие даёт неактивный статус.
- Числовые границы включены; особый случай `> 0` строго положителен: ноль не активирует условие.
- Отсутствие H₂ исключает HTHA даже при сохранённом старом pH₂; неизвестное присутствие водорода не заменяется числовым вводом. При отсутствии хлоридов используется ноль; старое ppm без признака присутствия трактуется как присутствие по правилу проекта.
- Условия компонентов показаны справочно, не участвуют в статусе потока. Результат содержит объяснения, фактические значения, принятые пороги/зоны, комментарии, признак переопределения, engine_version и signature. Комментарии и порядок ключей не изменяют расчётную сигнатуру.

## API и интерфейс

GET /api/process-flows/schema возвращает базу screening. GET /api/process-flows/{id} возвращает сохранённое screening и пересчитанный screening_result (null для неподходящих потоков). PATCH той же карточки принимает screening вместе с паспортом/составом, под общей version. Сохранение атомарно; owner/admin пишут, member читает. Конфликт — 409 с сохранением черновика. Ответы, комментарии и пороги попадают в историю потока; приватные данные других тенантов недоступны. Миграция применяется ко всем готовым tenant-БД через tenant:migrate.

React использует отдельные FlowScreeningPanel/screening и общий редактор карточки/guard. Есть неизвестно/да/нет, комментарии, числовые ответы, явное применение pH из сохранённых параметров, редактирование и сброс порогов, явное применение зоны 20%, фильтр механизмов. При правке показывается, что статусы относятся к сохранённым данным; пересчёт выполняется после сохранения на сервере. pH/хлориды и pH₂ блокируются по наличию воды/хлоридов/водорода без удаления исходных значений. Содержимое закрытых секций не создаётся в DOM.

## Проверки и границы

125 backend-тестов / 1408 assertions проходят. Новые проверки включают 24 набора, 504 статуса механизмов, сверенных с исходным JS-ядром; точные границы/зоны/нулевой порог, неизвестные значения, сброс порогов, роли/тенанты и конфликт. В настоящем React/Laravel/PostgreSQL проверены запись, чтение во втором независимом сеансе и 409 без потери черновика. Временный tenant/роль/БД/пользователи после проверки удалены.

Storybook: ScreeningUnknown, ScreeningActive, ScreeningAttention и прежние состояния потоков. Браузерные команды: npm run test:flows:browser и npm run test:screening:browser; новый набор входит в test:api:browser. Проверяются комментарии, 0/false, статусы, фильтр, сброс/20%, guard, readonly и отложенное создание DOM.

Остаются отдельными задачами: подбор репрезентативной среды F10.06, tenant-справочник принятых общих порогов RUS/ENG и процента подсказки, подсказки по составу/pH₂, компонентный/сторонний скрининг F17.04–05, отметка проверки результата, неизменяемые снимки/зависимости DF и импорт mdOv/mdChk/mdMan. Локальные refOv старой модели скрыто не подмешиваются в серверные правила. Этот срез не закрывает F17 целиком.
