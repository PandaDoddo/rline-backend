# Назначения потоков оборудованию

Срез 08.11.2026: базовые F11.01–04 и React-вкладка «Потоки» подключены. Миграция 000014 добавляет контакты, строки назначений и пространство компонента. Данные сохраняются атомарно вместе с паспортом, компонентами и замерами через PATCH /api/equipment/{equipment}; общая версия ЕО защищает от конфликта. Чтение — поле flows подробной карточки, в реестр оно не включается.

## Область и наследование

Области: ЕО по умолчанию, трубное/межтрубное пространство и компонент/элемент по UUID. Стороны: внутренняя, наружная, обогрев, изоляция. Пространства задают внутреннюю среду; для трубного пучка трубное пространство относится к внутренней стороне, межтрубное — к наружной. Для других компонентов flow_space задаётся во вкладке компонентов.

Режимы различаются: assign — явный список потоков, none — подтверждаемое явное отсутствие, inherit — продолжить поиск на вышестоящем уровне. Если источника нет, результат unknown. Порядок: элемент → компонент → пространство → ЕО. Змеевик и его элементы не наследуют назначения сосуда; их цепочка заканчивается на самостоятельном компоненте змеевика. Явное отсутствие прерывает поиск. Обогрев/изоляция не используют назначения внутренней стороны.

Демонтаж не удаляет UUID, назначения или историю; эффективная строка помечается неактивной, восстановление возвращает прежние ссылки. Новая правка назначения демонтированного компонента запрещена до восстановления.

## Проверки и режимы

Внутрь нельзя назначить наружный поток; наружу/изоляции назначаются наружные потоки, изоляции — среда insulation. Все потоки относятся к установке ЕО; группа не является потоком. Архивные назначения сохраняются и показываются с предупреждением; новые ссылки на архив запрещены. Перенос ЕО на другую установку требует явного снятия старых ссылок в том же сохранении.

Доли альтернативных режимов хранятся в процентах года, 0 отличается от неизвестного null. Сумма известных долей не превышает 100 %. Остаток основных режимов выдаётся только при наличии основного потока и известных долях всех альтернативных; между несколькими основными потоками он автоматически не распределяется. Временные периоды и агрегация в DF остаются отдельной задачей.

Проверка имеет автора и дату. Для правки проверенного назначения требуется явная разблокировка; можно снять, изменить и повторно проверить за одну транзакцию. Наследование, неизвестные доли альтернативных и архивные потоки проверить нельзя. Принятая версия потока хранится в строке; изменение потока показывает stale, не переписывая прежнее подтверждение. Повторная явная проверка принимает текущую версию.

## Целостность и загрузка

Контакты и строки имеют UUID, внешние ключи и уникальность области/стороны и потока внутри назначения. Чужой UUID нельзя переиспользовать или перенести; вставка нового UUID не выполняется через upsert. Версии и проверки валидируются под блокировкой ЕО, используемые потоки блокируются в устойчивом порядке. Любая ошибка откатывает паспорт, структуру и назначения целиком.

Права owner/admin и tenant-изоляция общие с карточкой; member читает. Пропущенные контакты сохраняются, сброс — явный режим inherit. До 2000 областей, 100 потоков на область, 5000 связей на ЕО. Чтение контактов и метаданных потоков выполняется пакетно без N+1. Эффективные строки ссылаются на contact_id, не копируют состав каждого назначения. React выводит по 25 компонентов (100 сторон), каталог потоков запрашивается только при открытом выборе и читается страницами.

Нагрузочный пример: 500 компонентов × 4 стороны × 100 потоков. Развёрнутый сырой JSON — 47 565 310 байт, общий список + ссылки — 405 310 байт, в 117,36 раза меньше. Это синтетический размер без HTTP-сжатия, не замер времени сети. EquipmentFlowProjectionTest защищает отсутствие повторов и верхнюю границу размера.

## Границы и проверка

EquipmentFlowContactsTest проверяет атомарность, чужие ID, доли, архивы, наследование, независимый змеевик, пучок, запрет переноса, демонтаж/восстановление, проверки и роли. Браузерный набор npm run test:flow-contacts:browser — сохранение, 0 %, блокировка, none/inherit, Escape/guard, ограничение таблицы, member/409. В Storybook четыре состояния вкладки в оболочке карточки ЕО. Реальная приёмка testing contacts-20261108-25 выполнена на временных данных PostgreSQL; данные удалены.

История назначений входит в агрегатный аудит ЕО. Полный журнал изменений отдельных назначений, импорт eqFlow/efUnit, массовая замена, временные периоды и уведомление зависимых расчётных снимков требуют последующих частей F11/F25. Изменение каталога вещества без изменения версии потока пока отдельно не инвалидирует контакт; смесь отслеживает такую зависимость собственной сигнатурой. Утверждение правил агрегации DF из BACKLOG не подменяется процентами контакта.
