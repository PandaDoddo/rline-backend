# Компонентный скрининг МД

Состояние 10.11.2026. Работа только локальная. Это скрининг применимости, а не сохранённый расчёт DF/PoF/CoF/риска.

## Владельцы данных

Миграция 000067 уже применена после `.tools/rline-before-mechanism-inputs.dump`; её семантику и используемый frozen `component-screening-v1.json` не менять. Числа/boolean/null — отдельные типизированные колонки, ответы расчёта не сохраняются в mutable JSON.

- Общие входы ЕО: вибрация, резервное pH₂ и пояснения. В HTHA значение потока имеет приоритет; резервное давление применяется при подтверждённом наличии H₂ и отсутствии числа в потоке. Явное отсутствие H₂ не переопределяется резервным числом.
- Настройки компонентов: исключение вибрации, днище на грунте, пояснения. Наследование по структуре; явное `false` останавливает наследование.
- Переопределение: элемент + механизм + физическая сторона; статус, обязательное обоснование, подпись автоматических входов. Устаревший статус сохраняется как факт, но не участвует в расчёте.
- Комментарий: элемент + вопрос + сторона + поток (nullable для контекста без потока). Ключ неизменяемый, SQL проверяет установку потока. Новая запись через API допустима только для текущего вопроса/контакта; старую можно явно сбросить.
- Подтверждение: физический элемент + подпись расчёта и комментариев, автор/время сервера. UPDATE подписи запрещён SQL, переподтверждение создаёт новую запись. Неизменённое подтверждение сохраняет прежнего автора. Для правки проверенных входов/комментариев сначала снять подтверждение; внешние изменения паспорта/материала/потока делают его устаревшим.

## Вычисление и контекст

`Equipment/Domain/Screening`: 32 МД / 88 вопросов. AND внутри одного потока, OR между потоками. Внутренняя, наружная и сквозная стороны независимы; один явно назначенный поток может контактировать с обеими сторонами. Ремонтные процессы не становятся технологическим воздействием.

Материал разрешается по точному имени активной марки. Архивная/неоднозначная/неизвестная марка не угадывается. Параметры змеевика и трубного пространства самостоятельные. Согласно AGENTS.md:409, T/P карточки/пространства имеют приоритет; при отсутствии — параметры конкретного назначенного технологического потока. Отсутствие обоих источников остаётся неизвестным. Для наружных механизмов без технологического контекста не выбирается произвольный первый поток.

`MechanismContextProvider` читает нужные марки/потоки пакетно, при записи удерживает source locks. `MechanismAssessment` повторно использует одинаковые контексты внутри запроса; межзапросного невалидируемого кеша нет. Подпись не включает версию самой ЕО, иначе подтверждение инвалидировалось бы собственным сохранением. Версии внешних потоков/марок включаются.

`FlowScreening` использует `flow-screening-v2.json`: нормализация Unicode-минуса исправляет два значения −12. Исходный v1 сохранён для старой миграции. Экспортёр не перезаписывает другой frozen-файл.

## API и интерфейс

`GET /api/equipment/{equipment}` — сводные состояния, входы, ручные факты, подписи и подтверждения. Полные вопросные трассы в сводке пусты для ограничения ответа. Активность передаётся в категории инспекций без скрытого mock.

`GET /api/equipment/{equipment}/components/{component}/mechanisms` — вопросы/условия конкретного физического элемента. Read-only snapshot, 404 для чужого/нефизического владельца.

`PATCH /api/equipment/{equipment}` — секция `mechanisms`, `schema_version=component-screening-v1`; `inputs`, `component_inputs`, `overrides`, `question_notes`, `reviews` являются частичными изменениями. Пустые/неизвестные значения не превращаются в `false` или `0`. Сброс статуса/комментария — явный null; снятие подтверждения — verified=false. Версия агрегата обязательна; несовпадение подписи входов — 409, неправильные владельцы/координаты/обоснование — 422. Авторов/время/расчётные результаты передавать нельзя. Права записи — owner/admin. Общая команда используется и вне HTTP; установка/ЕО и source locks удерживаются в общей транзакции.

React-вкладка: матрица и список по сторонам с виртуализацией, все четыре фильтра статуса, закреплённое наименование, вопросы выбранного элемента по запросу. Подсказки по недостающим данным ведут в паспорт/компоненты/потоки; критерии материала указывают на марочник. Черновые входы не меняют отображаемый сохранённый расчёт; перед подтверждением требуется сохранить и прочитать результат. Все вопросы имеют поле комментария. Storybook явно синтетический, расчёт и подтверждения не симулирует.
