# Хранение каталога веществ

Продолжение 10.11.2026, миграция 000056. Изменяемые значения вынесены из `substances.overrides` в `substance_properties`: отдельные типизированные колонки для 73 редактируемых свойств. Корневая запись содержит идентичность, статус, версию и неизменяемый базовый снимок. Справочный `mix` принадлежит базовому снимку и не редактируется.

`substance_property_annotations` связывает вещество с известным полем и хранит наличие переопределения, явное состояние неизвестности, источник и проверку. Численные факты не хранятся в универсальном JSON или строковом EAV-значении. Явное очищение — `value_present=true` и SQL NULL; отсутствие переопределения — отсутствие такого признака. Поэтому очистка не подставляет базовое значение, а сброс правки возвращает его. Ноль и false сохраняются своими типами.

Допустимые состояния (`не установлено`, `не определено`, `не применимо`, для IDLH также `простой асфиксиант`) связаны с конкретным полем составным FK. Отложенные ограничения не допускают одновременно число и состояние неизвестности, скрытое число без признака наличия, проверку пустого значения и переопределение read-only поля. Источник и проверка имеют парные автора/дату; источник может описывать также базовое значение без переопределения.

`substance_cards` — SQL-проекция прежней формы API (`overrides`, `sources`, `checks`). Она собирает документ чтения, не служит изменяемым хранилищем. Полные карточки загружаются пакетной Eloquent-связью; список и разрешение состава выбирают необходимые поля через SQL. `CatalogRecords` остаётся общим прикладным путём записи, для веществ делегирует физическое хранение `SubstancePropertyRepository`; аудит, версии, права и HTTP-контракт сохраняются.

Схема `resources/schemas/substance-properties-v1.json` и SQL-проекция `substance-cards-v1.sql` зафиксированы для миграции. Изменение набора полей требует следующей миграции; тест сверяет runtime-контракт и схему. `tools/export-substance-projection.php` проверяет воспроизводимость и запрещает переписывать выпущенную версию другим SQL.

Миграция переносит значения и свидетельства, сравнивает JSON-проекцию с прежним содержимым до удаления колонок. Неизвестный ключ или расхождение отменяют всю DDL-транзакцию. Откат собирает текущие значения обратно, включая последующие правки. Проверены перенос/откат, неизвестный ключ, ноль/false/null, состояния, запреты непосредственной SQL-записи и повтор импорта после ручных изменений. 000056 применена к локальному rline после резервного дампа; preview всех 62 правок каталога с потоками/контактами прошёл с откатом. Публичный сервер не обновлялся.
