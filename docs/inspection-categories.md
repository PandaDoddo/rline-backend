## Факты и календарь

Этап принадлежит ЕО и группе thin/ext/cui/cl/scc/hic/aus. Источник — выполненная диагностика или внеплановая дата. Наблюдение принадлежит этапу и физическому элементу, содержит nullable category (A–E/none) и nullable cracks_present. Отсутствие override означает авто; none — явно не учитывать; false — трещин нет; null — не известно. Группа aus сохраняет объединённую старую PASCC/ClSCC internal, не дублирует одно наблюдение в два независимых осмотра.

Чтение не материализует пустые календарные этапы. Источники дат:

- thin: выполненные ТО-1/ТО-2/ЭПБ/УЗТ и внеплановые замеры толщины.
- ext/cui/cl: ТО-1/ТО-2/ЭПБ/НО и внеплановый ВИК.
- scc/hic/aus: ТО-1/ТО-2/ЭПБ и собственные ручные даты группы.

Совпавшие даты показывают высший вид. SQL и guardDiagnostics не позволяют осиротить сохранённые факты или молча объединить два этапа группы. Явный сброс этапа в той же команде разрешает снять исходную дату; вся команда атомарна. Факты неактивных/исторических элементов сохраняются и не участвуют в текущих числах.

## Автоматические категории и активность

InspectionCategoryRules сравнен с 16 независимыми сценариями old _dfCommon (tests/Fixtures/old-inspection-categories.json). Любой известный замер, включая ноль, означает замеренный CML; все точки CML заполнять для этого не требуется. Для сосуда внутренний осмотр + все CML = B, часть = C, без УЗТ = D. УЗТ без внутреннего осмотра = C при наличии замера. Для трубопровода УЗТ = C, отсутствие = E. Пустой внеплановый этап не даёт категории. ВИК: известное наблюдение/проверенный этап = B, частичный = C, нет сведений = E.

Разреженная серверная проекция возвращает automatic_category и отличающиеся automatic_observations, отдельно от ручных facts. Статусы применимости и N_A–N_D вычисляются отдельно; неизвестные и неактивные МД не дают подтверждённых инспекций. Ext и CUI не делят один осмотр, неизвестная изоляция не даёт ложного счётчика.

Компонентный скрининг МД ещё в работе. В реальном API applicability пока unknown (физически несовместимые/демонтированные элементы исключаются); это не готовый расчёт активности. Реальные ручные ячейки UI ожидают активного МД, импортированные факты доступны справочно. Storybook явно использует синтетические известные статусы для проверки редактирования. Чистый потоковый скрининг не заменяет компонентный скрининг по материалу и стороне.

## API и UI

GET карточки содержит inspection_categories; каталог — inspection_category_schema. PATCH под общей version ЕО принимает schema_version, изменённые stages/observations, reset_components и delete_stage_ids. Проекции, счётчики, авторы и активность из клиента не принимаются. Аудит хранит реальные before/after. Member читает, admin/owner пишет; архивные ЕО и демонтированные элементы защищены.

React: отдельная вкладка, выбор группы, все/МД элементы, демонтаж, ручные даты SCC/HIC/aus, bulk для активных элементов, Enter к следующей доступной строке, закреплённые четыре колонки. Виртуализация строк и дат: Storybook 1201 элемент ×120 дат/группа → 16–18 строк и 11–14 дат в DOM, 1090–1355 узлов (это не временной benchmark). CSV экспортирует отдельные manual/automatic facts и независимые crack answers.
