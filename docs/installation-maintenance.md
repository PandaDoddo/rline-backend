# МРИ, ремонты и внеплановые остановы

Срез 08.11.2026: серверное хранение и вкладки прежней карточки установки. Новые записи имеют устойчивые UUID и пустые исходные поля; даты и интервал не генерируются.

## Записи и правила

- `mri`: effective_date (дата), interval_months (1–1200 целых месяцев), reason (основание).
- `repair`: starts_on/ends_on (даты), repair_kind (capital / extended_medium / medium), reason (примечание).
- `stop`: starts_at/ends_at (ISO 8601 с явным смещением), reason (причина). Сервер сохраняет UTC; React вводит и показывает время в часовом поясе браузера, который подписан на странице.

Неполную запись можно сохранить, но нельзя проверить. Окончание раньше начала отклоняется атомарно. Для одной даты МРИ допускается одна действующая запись. Вид существующей записи не меняется, UUID удалённой записи не используется заново. Удаление мягкое, история сохраняется. Все записи принадлежат одной установке и tenant-БД.

Проверка содержит пользователя и время сервера. Проверенная строка не редактируется/не удаляется; UI позволяет явно снять проверку, исправить и проверить заново одним сохранением (`unlock`). Для удаления ранее проверенной строки сначала нужно сохранить снятую проверку. Неизвестные поля и поля другого вида записи отклоняются.

`no_stops=null` означает, что сведений об отсутствии остановов ещё нет; `true` — явное подтверждение. Нельзя совместить это подтверждение с записями остановов, даже на другой странице списка. Добавление после подтверждения требует явно снять его.

## Итоги

Действующий МРИ — последняя полная запись по дате; будущая дата помечается предупреждением. Последний завершённый капитальный ремонт имеет заполненные даты и окончание не позже серверной даты. План = окончание этого ремонта + МРИ, календарные месяцы без переполнения дня (31 января + месяц = последний день февраля). Просроченный план не переносится автоматически. Пустой МРИ или отсутствие завершённого капитального ремонта не заменяются текущей датой.

По ремонту показывается число диагностик ЕО установки, у которых последнее выполнение соответствующего вида попало в период ремонта. Ранние повторения того же вида не увеличивают счётчик.

Окно остановов — предыдущие 12 месяцев до серверного `as_of` (UTC). Интервалы обрезаются по границам окна и объединяются PostgreSQL `range_agg`, поэтому пересечения не удваивают простой. Неполные интервалы исключаются с предупреждением. `downtime_complete` отличает полный итог от суммы заполненных интервалов; пустой неподтверждённый список не доказывает отсутствие простоев. Полные потери `production_loss` выдаются только при известных prodcost и сведениях об остановах. `known_production_loss` — сумма по заполненным интервалам; это не полный итог. Явный prodcost=0 сохраняет нулевой результат.

## API, версии и аудит

- GET `/api/installations/{uuid}/maintenance?kind=mri|repair|stop&page=1&per_page=50` — до 100 записей на страницу, общая версия установки.
- GET `/api/installations/{uuid}/maintenance/summary` — компактная сводка, версии/дата источника и предупреждения.
- PATCH `/api/installations/{uuid}/maintenance` — version, upserts (до 200), delete_ids (до 200), optional no_stops. Поля записи разреженные; отсутствие поля сохраняет его прежнее значение, null очищает.
- GET `/api/installations/{uuid}/maintenance/events` — последние 200 сохранений по 30 на страницу; полный аудит сохраняется. Различия показываются по UUID записи и отдельным полям.

Паспорт, затраты и обслуживание используют одну блокировку и версию установки. Любая конкурирующая правка даёт 409 без частичных записей; React сохраняет черновик. Owner/admin пишут, member читает. Чужие/удалённые UUID не доступны. List и summary читаются в REPEATABLE READ; если отдельные ответы получили разные версии, интерфейс блокирует начало правки и предлагает обновить данные.

## Проверки и границы

Проверены PostgreSQL-изоляция, роли, 409/rollback, частичные значения, проверки/разблокировка, мягкое удаление/история, 65 записей с пагинацией, диагностики ремонта, пересечения и границы годового окна. В Storybook — пусто/заполнено/130 записей/остановы/member/conflict/error/loading. Браузерный сценарий — `npm run test:maintenance:browser`, нормализация — `npm run test:maintenance`.

На testing проверены настоящие записи, план капитального ремонта, совместная работа с затратами, union остановов/потери, повторное открытие и глобальная защита черновика. Временные данные удалены.

Пока не подключены подсветка сроков диагностик относительно ремонтов в реестре/графиках, полная лента ФТС, импорт старых записей и общая готовность/проверка шагов. Это не закрывает всю F03.
