# ВИК — визуальные наблюдения физических элементов

Статус 10.11.2026: реализованы PostgreSQL-модель (миграция 000064), общие команды/валидация, карточка API, React/Storybook и начальный атомарный импорт. Локальная миграция применена после дампа; публичный сервер не обновлялся. Требования — AGENTS.md, раздел «ВИК — наружная коррозия». В old сохранены только EQ0007: 28 наблюдений по двум датам, все с физическим владельцем; явное «нет» отличается от отсутствия сведений.

## Границы

- Этап ВИК: UUID, EO, связанная диагностика (либо отдельный внеплановый этап), фактическая дата, текущая проверка/автор/время. Плановые колонки по фактическим ТО-1/ТО-2/ЭПБ/НО; в одну дату показывается высший вид. Факт ВИК может быть раньше диагностики, позже — аномалия. Источник old __vchk хранить отдельно от текущего подтверждения.
- Наблюдение: связь этап–физический элемент; стабильные UUID, без связи с позиционным индексом/CML. Типизированные поля: corrosion_present, corrosion_kind, severity, depth_mm, affected_area, area_unit, coating_condition, insulation_condition, cracks_present, partial, notes. Булевы три состояния, неизвестное не превращается в false.
- Наличие изоляции: отдельное nullable override по элементу (null=авто), автоматическое по эффективному контакту insulation/ОС2. Отсутствие данных о контакте — неизвестность. Сосуд и каждый змеевик независимо.
- Коррозии нет/неизвестна: вид/степень/глубина/площадь не применяются; UI очищает их при смене. Старое противоречие сохранить в source issue, не терять молча. Глубина >= Sном разрешена как наблюдение, но даёт аномалию.
- У ВИК по умолчанию неизвестно, никакой скрытой генерации «нет». Категория B/C только при заполненной записи или явно проверенном этапе; иначе E. Частичный осмотр — C. Неизвестную изоляцию не выдавать за достоверный Ext/CUI.

## Найденные исходные значения

has/crk/part: да/нет/пусто; kind: сплошная/местная/язвенная/питтинговая; deg: нет/слабая/умеренная/сильная; coat: poor/medium/high; ins: below average/average/above average; areaU: %/м², в old пропущенное areaU у заполненной площади означает %. Пример K-02#S1 на 2023-06-16: коррозия да, местная, слабая, глубина 0,2 мм, площадь 5 %, coat poor, ins average, трещин нет.

В 2011-03-23 четыре строки; в 2023-06-16 — 24. Неиспользуемые даты не заполнять наблюдениями из пустого интерфейса. Карта source_alias → UUID берётся из component-structure.provenance.

## Связанные незавершённые части

icatOv EQ0007: 47 ключей (категории/трещины/флаг старой миграции), нужны нормализованные инспекционные факты до сборки DF. mdMan: vib=нет у EQ0045/EQ0038; mdOv/mdChk фактически пустые. Покрытие по змеевикам/трубному пространству пока не представлено в OperatingScopeSchema; не наследовать покрытие сосуда молча. В saved old cardOv таких scoped overrides нет, но полноценный ввод требует отдельного расширения схемы.

Builder сохраняет raw ВИК, категории, ручные механизмы, схему пучка и исторические DF/PoF/CoF/RISK в immutable evidence оборудования; они не становятся новыми принятыми расчётами.

## Контракт и ограничения

GET карточки возвращает visual_inspections: schema_version, stages, insulation_overrides, elements, scope_summaries, anomalies. Каталог оборудования содержит visual_inspection_schema. Чтение пустого календаря не создаёт записей. PATCH карточки требует текущую version; принимает только изменения фактов, сбросы наблюдений/этапов и nullable overrides изоляции. Вычисления, авторы и время проверки доступны только для чтения.

Проверенный этап сначала явно разблокируется; перед удалением этапа разблокировку нужно сохранить. Его фактическая дата и наблюдения, а также связанная дата выполненной диагностики защищены командами и SQL. Очистка непроверенного этапа диагностики сохраняет календарную колонку; удаление внепланового этапа удаляет колонку. Исторические наблюдения прежней детализации сохраняются, но не включаются в текущие показатели физического состава.

Таблица React виртуализирует строки и даты, закрепляет четыре левые колонки, разделяет сосуд и каждый змеевик. Массовое заполнение пропускает неактивные/неприменимые/проверенные ячейки. Сводка ФТС использует сохранённую серверную оценку. CSV включает даты, факты и категории. На большом Storybook-сценарии 1201 элемент/120 дат в DOM 16–18 строк, 3–4 группы дат; это число узлов, а не замер времени отклика или сравнение с old.

## Импорт и проверки

Private manifest equipment[].visual_inspections: stages [{id,source_date,measured_on,source_verified,observations}], insulation_overrides. Поле source_verified не переносится в текущую проверку. Дата источника сопоставляется высшему выполненному виду на эту дату (ЭПБ > ТО-2 > ТО-1 > НО); иначе создаётся внеплановый этап. После импорта публичные проекции независимо перечитываются: даты, владельцы, значения, отсутствие текущего проверяющего и overrides. Любое расхождение отменяет транзакцию.
