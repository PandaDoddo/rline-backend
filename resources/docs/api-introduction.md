# R-Line API

Спецификация автоматически строится Scramble по маршрутам, правилам валидации и коду ответов Laravel. Пояснения ниже описывают порядок работы с сеансом.

## Вход

1. Получите CSRF-cookie: `GET /sanctum/csrf-cookie`.
2. Выберите организацию: `POST /auth/tenant`, тело `{"tenant":"rline"}`. Передавайте тот же код в `X-Tenant`.
3. Получите доступные способы входа: `GET /auth/providers`.
4. Для Local/LDAP/AD отправьте `POST /auth/login` с `provider`, `email` (либо логином каталога), `password`.
5. Ответ `{"two_factor":true}` означает незавершённый вход: отправьте `POST /auth/two-factor-challenge` с `code` либо `recovery_code`.
6. `GET /auth/me` возвращает пользователя и тенанта. Если `user.two_factor_required=true`, а `two_factor_enabled=false`, перед обращением к предметным API необходимо настроить TOTP. При Local `require_totp=false` вход выполняется только по логину и паролю.

Multifactor начинает вход переходом браузера на `/auth/multifactor/redirect?tenant=rline`; callback обрабатывает приложение. Это перенаправление браузера, а не получение bearer-токена.

## Cookie, CSRF и тенант

Авторизация использует HttpOnly session cookie. `Authorization: Bearer` не требуется. Изменяющие запросы передают `X-XSRF-TOKEN`: URL-decoded значение cookie `XSRF-TOKEN`. Страница документации автоматически получает CSRF-cookie и добавляет заголовок к запросам на этот сервер. Пароль, TOTP и резервные коды вводятся только в соответствующие запросы и не сохраняются в спецификации.

`X-Tenant` — код организации, пример `rline`. Подмена заголовка не переключает авторизованный сеанс: выберите организацию через `/auth/tenant` и войдите заново. Один сеанс относится к одному тенанту. Настройки провайдеров возвращают признаки наличия секретов, без их значений.

## Отказы

- `401` — нет действующего сеанса либо настройки входа изменились.
- `403` — недостаточно прав, заблокировано членство или требуется настройка MFA.
- `404` — организация/объект недоступны.
- `409` — запрос относится к другой организации, чем сеанс.
- `410` — подтверждение MFA истекло, использовано либо идентичность изменилась.
- `419` — CSRF-cookie/заголовок недействительны.
- `422` — неверные поля, реквизиты или код подтверждения.
- `429` — превышено число попыток.

Создание тенанта требует полномочий платформы и запускает подготовку БД в фоновой задаче. Проверяйте статус в списке тенантов. Инструкции подключения находятся в `docs/authentication.md` и `docs/tenancy.md` репозитория backend.
